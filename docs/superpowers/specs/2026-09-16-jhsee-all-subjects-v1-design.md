# JHSEE 全科會考模擬學習平台 V1.0 設計計畫書

日期：2026-09-16
專案：JHSEE-All-Subjects
目標考試：116 年（2027）國中教育會考
部署目標：GitHub Pages

## 1. 專案目標

建立一套全新的國中教育會考全科學習與模擬平台，不依賴既有 JHSEE-English-Adventure。平台涵蓋國文、英語、數學、社會、自然及寫作，核心目標是讓學生能在手機或電腦上完成「單元練習 → 單科模擬 → 全真模擬 → 成績分析 → 錯題複習」完整閉環。

V1 優先確保考試流程穩定、題庫可維護、資料來源標示清楚、離線前端可運作。AI 自動產題、登入及雲端同步保留為後續版本，不納入 V1 核心依賴。

## 2. 核心原則

1. 官方歷屆試題與自製模擬題必須分庫、分標籤，不得混淆來源。
2. 每題必須具備科目、單元、題型、難度、來源、答案與解析等結構化欄位。
3. V1 採靜態前端架構，可直接由 GitHub Pages 部署，不需要伺服器即可完成主要功能。
4. 學生資料預設只存在瀏覽器 LocalStorage，不要求帳號。
5. 手機優先，同時支援桌面瀏覽器。
6. 題庫與 UI/考試引擎分離，避免增加題目時修改核心程式。

## 3. 使用者主要流程

### A. 首頁

首頁提供：
- 116 年會考倒數
- 「開始全真模擬」主要入口
- 六大科目入口：國文、英語、數學、社會、自然、寫作
- 最近一次測驗摘要
- 弱點單元摘要
- 錯題待複習數
- 歷屆官方試題入口

### B. 單元練習

學生選擇科目、年級/範圍、單元、題數與難度後開始練習。練習模式允許交題後立即查看答案與解析，並將錯題加入錯題本。

### C. 單科模擬

學生選擇單一科目進行較接近正式考試的測驗。測驗開始後顯示計時器、題號導航、已答/未答狀態及標記題目功能。正式交卷前不顯示答案。

### D. 全真模擬

以考試模式組合各科測驗。V1 的架構允許依正式考試規格設定各科題數、時間與題型；這些規格集中在設定檔，不硬編碼於畫面。學生完成後進入總成績 Dashboard。

### E. 成績與複習

交卷後提供：
- 總題數、答對數、正確率
- 各單元正確率
- 題型表現
- 作答時間
- 錯題列表
- 每題答案與解析
- 再練一次錯題
- 歷次測驗趨勢

平台不得把自製模擬題成績直接宣稱為官方會考等級；若未來提供能力區間估計，必須明確標示為模擬分析而非官方成績。

## 4. 科目模組

### 國文
支援語文基礎、閱讀理解、文意判讀、跨文本及圖表/情境整合等題型。

### 英語
分為閱讀與聽力資料結構。聽力題需支援音訊 URL 或瀏覽器語音等媒體欄位，但官方題目的音訊來源必須合法且可追溯。

### 數學
支援選擇題及非選擇題。V1 非選擇題先支援文字/數值作答與參考解析；人工式分步評分列為後續增強項目。

### 社會
題庫標記歷史、地理、公民子領域，支援文字、地圖、表格與情境材料。

### 自然
題庫標記生物、理化、地球科學等領域，支援實驗情境、圖表與計算題。

### 寫作
提供會考型寫作題目、引導材料、作答區、字數統計、草稿保存及評分規準說明。V1 不宣稱 AI 自動給出官方級分。

## 5. 題庫資料架構

建議目錄：

```text
data/
  official/
    115/
      chinese.json
      english.json
      math.json
      social.json
      science.json
  mock/
    chinese.json
    english.json
    math.json
    social.json
    science.json
    writing.json
```

每題最少包含：

```json
{
  "id": "mock-math-001",
  "subject": "math",
  "domain": "algebra",
  "grade": [7, 8, 9],
  "type": "single-choice",
  "difficulty": 2,
  "sourceType": "mock",
  "sourceLabel": "平台自製模擬題",
  "stem": "題幹",
  "choices": ["A", "B", "C", "D"],
  "answer": 1,
  "explanation": "解析",
  "tags": ["一次方程式"]
}
```

官方題另增加 year、examName、sourceUrl/sourceNote 等來源資訊。若題目包含圖片、表格或音訊，使用 media 欄位引用資產。

## 6. 前端架構

V1 採 HTML + CSS + JavaScript 模組化靜態網站，避免一開始引入不必要的框架與建置依賴。

建議結構：

```text
index.html
css/
  base.css
  components.css
  exam.css
js/
  app.js
  router.js
  storage.js
  question-bank.js
  exam-engine.js
  scoring.js
  analytics.js
  subjects/
    chinese.js
    english.js
    math.js
    social.js
    science.js
    writing.js
data/
assets/
tests/
```

各模組責任：
- `question-bank.js`：載入、驗證與篩選題庫。
- `exam-engine.js`：建立試卷、切題、計時、標記、暫存答案、交卷。
- `scoring.js`：客觀題批改與統計。
- `analytics.js`：單元/題型弱點與歷次趨勢。
- `storage.js`：LocalStorage schema、版本與資料存取。
- `subjects/*`：科目特有顯示/行為，不承擔共用考試流程。

## 7. LocalStorage 資料

使用具版本號的單一 namespace，例如 `jhsee.v1.*`。保存：
- 使用者設定
- 進行中的測驗
- 歷次測驗摘要
- 錯題 ID 與錯誤次數
- 收藏/標記題目
- 寫作草稿

不保存敏感個資。資料 schema 改版時需提供 migration 或安全重置策略。

## 8. 考試引擎規則

考試引擎必須支援：
- 固定或隨機題序
- 題庫條件篩選
- 題號導航
- 已答/未答/標記狀態
- 倒數計時
- 自動暫存答案
- 重新整理後恢復未完成考試
- 交卷確認
- 時間到自動交卷（可由模式設定）
- 考試模式交卷前禁止顯示正解

試卷設定獨立於題庫，例如 subject、durationMinutes、questionRules、shuffle 等，以便未來調整正式會考規格時不重寫引擎。

## 9. 成績分析

V1 Dashboard 至少呈現：
- 正確率
- 科目/子領域正確率
- 單元弱點
- 難度分布
- 平均每題時間
- 歷次測驗趨勢
- 錯題累積與改善狀況

弱點判定以透明規則實作，例如達到最小作答樣本後，依正確率排序；樣本不足時標示「資料不足」，避免過度推論。

## 10. 官方歷屆題與內容治理

官方題庫頁面與模擬題頁面視覺上明確區分。匯入官方題目前，需核對官方公布資料、題目版本、答案及可使用的來源方式。系統保留來源欄位，不把第三方整理內容冒充官方資料。

自製題必須標記「模擬題」。未經人工審核的 AI 題未來若加入，需另標記 `ai-generated` 與審核狀態。

## 11. UI/UX 方向

整體採正式 CBT（Computer-Based Testing）學習平台風格，不沿用英文 Adventure 的遊戲視覺。

首頁強調：
1. 會考倒數與今日狀態
2. 開始全真模擬
3. 六科入口
4. 成績/弱點/錯題摘要

考試頁優先確保閱讀性：題幹區、選項區、題號導航與計時器固定清楚；手機版避免橫向捲動，圖表可縮放查看。

## 12. 錯誤處理

- 題庫 JSON 載入失敗：顯示可理解錯誤，不進入空白考試。
- 題目 schema 不合法：跳過問題題目並記錄診斷，不讓整份考卷崩潰。
- LocalStorage 不可用/容量不足：提示使用者並允許繼續本次測驗。
- 重新整理/意外關閉：優先恢復未完成測驗。
- 圖片/音訊失敗：顯示替代訊息並標記該題媒體異常。

## 13. 測試策略

核心邏輯必須可獨立測試，至少覆蓋：
- 題庫 schema 驗證
- 題目篩選與抽題
- 答案記錄
- 客觀題計分
- 計時與到時交卷
- LocalStorage 儲存/恢復
- 錯題本新增/移除/重做
- 弱點統計
- 官方題與模擬題來源隔離

另進行桌面與手機瀏覽器手動驗證，確認 GitHub Pages 子路徑部署不造成資源 404。

## 14. V1 開發階段

### Phase 1 — Foundation
建立設計系統、首頁、路由、資料 schema、Storage 與基本測試環境。

### Phase 2 — Exam Core
完成題庫載入、考試引擎、答案卡、計時、交卷與計分。

### Phase 3 — Subjects
依序接入國文、英語、數學、社會、自然、寫作模組與示範題庫。

### Phase 4 — Review & Analytics
完成錯題本、詳解、弱點分析、歷史紀錄與 Dashboard。

### Phase 5 — Official Archive
建立官方歷屆試題專區及來源治理流程；官方題目經核對後分批匯入。

### Phase 6 — QA & Deployment
手機/桌面 QA、資料完整性檢查、GitHub Pages 部署及回歸測試。

## 15. V1 驗收條件

V1 完成時必須能做到：
1. GitHub Pages 可由手機與桌面正常開啟。
2. 首頁可進入六科及全真模擬入口。
3. 至少有一組跨科完整示範模擬流程可從開始做到交卷。
4. 客觀題可自動批改並顯示解析。
5. 測驗中重新整理可恢復進度。
6. 錯題可進入錯題本並再次作答。
7. Dashboard 可顯示歷次測驗與弱點統計。
8. 官方題與模擬題在資料與 UI 上均清楚隔離。
9. 核心測試通過，且沒有已知會阻斷作答流程的錯誤。

## 16. V1 不納入範圍

為避免第一版過度膨脹，以下延後：
- 使用者登入/會員系統
- 跨裝置雲端同步
- Supabase/Firebase 等後端
- OpenAI API 自動出題
- AI 作文自動正式級分判定
- 教師班級管理後台
- 排名/社群功能

上述功能的介面可預留，但不得成為 V1 完成的前置條件。

## 17. 後續版本方向

V1 穩定後可依序評估：
- V1.5：完整題庫擴充、更多模擬卷、PWA/離線能力。
- V2：AI 弱點推薦與經審核的自動出題流程。
- V2.x：帳號、雲端同步、跨裝置學習紀錄。
- V3：教師/家長 Dashboard、班級與學習任務管理。

## 18. 成功定義

這個專案的第一成功標準不是「題目很多」，而是學生可以可靠地完成一次完整測驗，得到可理解的結果，知道自己錯在哪裡，並能回到對應弱點繼續練習；同時題庫來源與模擬/官方身份始終清楚可追溯。
